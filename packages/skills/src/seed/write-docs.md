---
name: write-docs
description: Write or update user-facing documentation for a feature or API.
appliesTo: plan, implement, review
keywords: docs, documentation, readme, guide, tutorial, howto, docstring, comment
---

Runbook:
1. Identify the audience: end user, integrator, or contributor. Match tone to it.
2. Lead with a concrete example. Show inputs and outputs before explaining internals.
3. Keep prose tight. Prefer bullet lists to paragraphs. Prefer tables to bullet lists for parallel content.
4. Cross-link related pages / files. Do not duplicate content that lives elsewhere.
5. Update table-of-contents / index if one exists.

Report: doc file(s) touched, and whether an example was included.
